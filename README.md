# RAINS WorkOS

Welcome to **RAINS WorkOS** — the engineering workspace for RAINS.

This organization contains the software, services, infrastructure, and supporting tools used to build and operate RAINS WorkOS.

## Projects

Our repositories contain different parts of the RAINS WorkOS ecosystem, including:

* Applications
* Backend services
* APIs
* Infrastructure
* Data and AI systems
* Shared libraries and tooling

See each repository's `README.md` for project-specific documentation.

## Development

Most repositories follow a common development workflow:

1. Create an issue describing the work.
2. Create a branch from `main`.
3. Implement the change.
4. Add or update tests where appropriate.
5. Open a Pull Request.
6. Request review from the appropriate team.
7. Merge after required checks and reviews pass.

See [`CONTRIBUTING.md`](./CONTRIBUTING.md) for contribution guidelines.

## Repository Standards

We aim to maintain:

* Clear documentation
* Small, reviewable Pull Requests
* Automated testing
* Consistent code quality
* Secure development practices
* Meaningful commit messages
* Clear ownership of systems and components

## Issues

Please use GitHub Issues for:

* Bug reports
* Feature requests
* Engineering tasks
* Documentation improvements
* Technical debt

Before opening a new issue, search existing issues to avoid duplicates.

## Security

Please **do not disclose security vulnerabilities through public GitHub Issues**.

If you believe you have discovered a security vulnerability, follow the instructions in [`SECURITY.md`](./SECURITY.md).

## Documentation

Project-specific documentation should live with the relevant repository.

Higher-level engineering documentation and internal processes may be maintained separately in the organization's private documentation.
